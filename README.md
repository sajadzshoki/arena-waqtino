# وقتینو — Waqtino

فرانت‌اند اپلیکیشن رزرو نوبت **وقتینو** — موبایل‌محور، فارسی‌محور، RTL، با Nuxt 4 + TypeScript + Nuxt UI. در نهایت با Capacitor به اپ اندروید تبدیل می‌شود. بک‌اند (AdonisJS) جداگانه است و در فازهای بعد از طریق لایهٔ سرویس متصل خواهد شد.

## شروع

```bash
npm install
npm run dev        # http://localhost:3000
```

اسکریپت‌ها:

| دستور | کار |
| --- | --- |
| `npm run dev` | سرور توسعه |
| `npm run lint` | ESLint |
| `npm run typecheck` | vue-tsc / nuxi typecheck |
| `npm run build` | بیلد پروداکشن |
| `npm run check` | lint + typecheck + build (گیت پایان هر فاز) |
| `npm run generate` | خروجی استاتیک (پیش‌شرط Capacitor) |

## حالت داده (mock / api)

پیش‌فرض `mock` است — بدون نیاز به بک‌اند. تنظیمات در `.env` (نمونه: `.env.example`):

```bash
NUXT_PUBLIC_API_MODE=mock        # mock | api
NUXT_PUBLIC_MOCK_OTP_CODE=1234   # فقط توسعه؛ کد ثابت ورود
```

### ورود آزمایشی (فقط حالت mock)

در صفحهٔ ورود، OTP ثابت (پیش‌فرض `۱۲۳۴`) چاپ می‌شود. شماره‌های از پیش‌شناخته‌شده،
سناریوهای قابلیت را فعال می‌کنند:

| شماره | قابلیت‌ها |
| --- | --- |
| `09111111111` | فقط مشتری |
| `09222222222` | مشتری + صاحب کسب‌وکار |
| `09333333333` | مشتری + کارمند |
| `09123456789` | هر سه قابلیت (پیش‌فرض) |
| هر شمارهٔ دیگر | کاربر تازه — فقط مشتری |

این نگاشت فقط در `app/services/mocks/users.ts` زندگی می‌کند و در Production UI
نمایش داده نمی‌شود.

## تغییر رنگ برند

فقط بلوک `--color-brand-*` در `app/assets/css/tokens.css` را ویرایش کنید؛
تمام تم لایت/دارک و کامپوننت‌های Nuxt UI خودکار به‌روز می‌شوند.

## ماندگاری در حالت mock

| چه چیزی | کجا | چرا |
| --- | --- | --- |
| نشست کاربر | کوکی `wq_session` | خوانده‌شدن در SSR ⇒ بدون hydration mismatch |
| حالت فعال (مشتری/صاحب/کارمند) | کوکی `wq_mode` | همان‌جا که نشست خوانده می‌شود |
| نشان‌شده‌ها + ویرایش‌های پروفایل | کوکی `wq_user_data` (به `userId` هر کاربر) | دادهٔ کاربر-محور؛ با سوییچ حساب قاطی نمی‌شود |
| ترجیح تم (سیستم/روشن/تیره) | `localStorage` با کلید `wq-color-mode` | اسکریپت ضدفلاش ماژول `@nuxtjs/color-mode` قبل از رندر اجرا می‌شود |
| خطاهای فرم، شیت‌ها، اسکرول، پیش‌نمایش آواتارِ فایل | هیچ‌جا | state گذراست؛ ماندگارکردنش اشتباه است |

## شبیه‌سازی حالت‌ها (فقط توسعه)

در `/dev/design` می‌توان همهٔ خواندن‌ها را روی «خطای شبکه»، «نتیجهٔ خالی» یا
«پاسخ ۴۰۱» گذاشت تا loading/empty/error/retry و مسیر «نشست نامعتبر → پاک‌سازی
مرکزی → هدایت به ورود» بدون بک‌اند قابل بررسی باشند.
