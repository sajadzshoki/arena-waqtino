# وقتینو — Waqtino

فرانت‌اند اپلیکیشن رزرو نوبت **وقتینو** — موبایل‌محور، فارسی‌محور، RTL، با Nuxt 4 + TypeScript + Nuxt UI. در نهایت با Capacitor به اپ اندروید تبدیل می‌شود. بک‌اند (AdonisJS) جداگانه است و در فازهای بعد از طریق لایهٔ سرویس متصل خواهد شد.

## شروع

```bash
npm install
npm run dev        # http://localhost:3000
```

اسکریپت‌ها:

| دستور | کار |
| --- | --- |
| `npm run dev` | سرور توسعه |
| `npm run lint` | ESLint |
| `npm run typecheck` | vue-tsc / nuxi typecheck |
| `npm run build` | بیلد پروداکشن |
| `npm run check` | lint + typecheck + build (گیت پایان هر فاز) |
| `npm run generate` | خروجی استاتیک (پیش‌شرط Capacitor) |

## حالت داده (mock / api)

پیش‌فرض `mock` است — بدون نیاز به بک‌اند. تنظیمات در `.env` (نمونه: `.env.example`):

```bash
NUXT_PUBLIC_API_MODE=mock        # mock | api
NUXT_PUBLIC_MOCK_OTP_CODE=1234   # فقط توسعه؛ کد ثابت ورود
```

### ورود آزمایشی (فقط حالت mock)

در صفحهٔ ورود، OTP ثابت (پیش‌فرض `۱۲۳۴`) چاپ می‌شود. شماره‌های از پیش‌شناخته‌شده،
سناریوهای قابلیت را فعال می‌کنند:

| شماره | قابلیت‌ها | برای چه آزمونی ساخته شده |
| --- | --- | --- |
| `09111111111` | فقط مشتری | حالت مشتری بدون فضای کاری؛ تب «صاحب کسب‌وکار» در سوییچر نیست |
| `09222222222` | مشتری + صاحب یک کسب‌وکار (باشگاه انرژی) | ورود خودکار به تنها کسب‌وکار؛ سوییچر لازم نیست |
| `09333333333` | مشتری + کارمند (کلینیک پارس) | مسیرهای مالک → «این بخش برای حساب شما فعال نیست» |
| `09123456789` | هر سه قابلیت + صاحب دو کسب‌وکار (نارنج، آینه) | پیش‌فرض: چند کسب‌وکار، سوییچ و انزوای داده |
| هر شمارهٔ دیگر | کاربر تازه — فقط مشتری | مسیر `/owner` بدون کسب‌وکار (با forceEmpty) |

این نگاشت فقط در `app/services/mocks/users.ts` زندگی می‌کند و در Production UI
نمایش داده نمی‌شود.

## تغییر رنگ برند

فقط بلوک `--color-brand-*` در `app/assets/css/tokens.css` را ویرایش کنید؛
تمام تم لایت/دارک و کامپوننت‌های Nuxt UI خودکار به‌روز می‌شوند.

## ساختار مسیرها

```
/login          مهمان: ورود با شمارهٔ موبایل
/login/otp      مهمان: تأیید کد

/               مشتری: خانه
/search         مشتری: جستجو
/business/[id]  مشتری: جزئیات کسب‌وکار
/booking        مشتری: جریان رزرو            [نیازمند ورود]
/booking/success مشتری: تأیید رزرو           [نیازمند ورود]
/bookings       مشتری: نوبت‌ها                [نیازمند ورود]
/saved          مشتری: نشان‌شده‌ها             [نیازمند ورود]
/profile        مشتری: پروفایل و حساب کاربری [نیازمند ورود]
/profile/edit   مشتری: ویرایش پروفایل        [نیازمند ورود]
/settings       مشتری: تنظیمات (تم، اعلان‌ها، خروج) [نیازمند ورود]
/notifications  مشتری: اعلان‌ها — آینهٔ «فعلاً در دسترس نیست» [نیازمند ورود]

/owner                          صاحب کسب‌وکار: ورود به فضای کاری (حل‌کنندهٔ زمینه)  [قابلیت business]
/owner/businesses               صاحب کسب‌وکار: فهرست کسب‌وکارهای قابل مدیریت        [قابلیت business]
/owner/business/[businessId]    صاحب کسب‌وکار: داشبورد همان کسب‌وکار                [قابلیت business]
/owner/business/[businessId]/info    صاحب کسب‌وکار: پروفایل، فقط‌خواندنی            [قابلیت business]
/owner/business/[businessId]/manage  صاحب کسب‌وکار: محور مدیریت + ردیف‌های «به‌زودی» [قابلیت business]

/employee*      کارمند               [قابلیت employee]

/dev/design     شوکیس سیستم طراحی + کلیدهای شبیه‌سازی mock — فقط محیط توسعه
```

`/owner` تنها ورودِ فضای کاری است: اگر یک کسب‌وکار داشته باشید یا انتخاب
ذخیره‌شده‌ای باشد، مستقیم به داشبورد همان کسب‌وکار می‌رود (با `replace`، تا
دکمهٔ «بازگشت» در چرخه نیفتد)؛ اگر چند کسب‌وکار داشته باشید و هنوز انتخاب
نکرده باشید، همان‌جا فهرست انتخاب می‌بینید.

## ماندگاری در حالت mock

| چه چیزی | کجا | چرا |
| --- | --- | --- |
| نشست کاربر | کوکی `wq_session` | خوانده‌شدن در SSR ⇒ بدون hydration mismatch |
| حالت فعال (مشتری/صاحب/کارمند) | کوکی `wq_mode` | همان‌جا که نشست خوانده می‌شود |
| کسب‌وکارِ زمینهٔ مدیر | کوکی `wq_owner_business` → `Record<userId, businessId>` | refresh همان کسب‌وکار را برمی‌گرداند؛ دو حساب روی هم نمی‌نویسند |
| نشان‌شده‌ها + ویرایش‌های پروفایل | کوکی `wq_user_data` (به `userId` هر کاربر) | دادهٔ کاربر-محور؛ با سوییچ حساب قاطی نمی‌شود |
| ترجیح تم (سیستم/روشن/تیره) | `localStorage` با کلید `wq-color-mode` | اسکریپت ضدفلاش ماژول `@nuxtjs/color-mode` قبل از رندر اجرا می‌شود |
| خطاهای فرم، شیت‌ها، اسکرول، پیش‌نمایش آواتارِ فایل | هیچ‌جا | state گذراست؛ ماندگارکردنش اشتباه است |

## سناریوهای آزمایش (فاز ۸ — فضای کاری مدیر)

با `npm run dev` و ورود به شماره‌های بالا:

| # | سناریو | انتظار |
| --- | --- | --- |
| ۱ | سوییچ به حالت «صاحب کسب‌وکار» (شیت هدر) | ورود به `/owner`، ناوبری پایین سه‌تبه می‌شود |
| ۲ | `09222222222` (یک کسب‌وکار) | بدون پرسش، داشبورد «باشگاه انرژی» باز می‌شود؛ دکمهٔ «تغییر» نیست |
| ۳ | `09123456789` (دو کسب‌وکار، انتخاب اول) | فهرست انتخاب در `/owner`؛ با انتخاب، داشبورد همان کسب‌وکار |
| ۴ | سوییچ از هدر (شیت «تغییر کسب‌وکار») | حین بارگذاری، نام/دادهٔ کسب‌وکار قبلی نمایش داده نمی‌شود (اسکلت) |
| ۵ | کسب‌وکار پرنوبت (نارنج) | نوبت بعدی + نوبت‌های امروز + سه شاخص |
| ۶ | کسب‌وکار بدون فعالیت (آینه) | «امروز نوبتی ندارید» + «قدم بعدی»؛ نوار آمار صفر نمایش داده نمی‌شود |
| ۷ | صاحب بدون کسب‌وکار: `npm run simulate:empty` | حالت خالی با توضیح؛ صفحه نمی‌شکند و به حالت مشتری پرتاب نمی‌شوید |
| ۸ | `/owner/business/biz_pars` (سارا آن‌جا کارمند است، نه مدیر) | «دسترسی به این کسب‌وکار ندارید» + راه بازگشت |
| ۹ | `/owner/business/invalid-id` | «چنین کسب‌وکاری پیدا نشد» + راه بازگشت |
| ۱۰ | refresh روی `/owner/business/biz_ayeneh` | همان کسب‌وکار، همان حالت، بدون از‌دست‌رفتن نشست/حالت |
| ۱۱ | سوییچ owner↔customer رفت‌وبرگشت | نشان‌شده‌ها/پروفایل/زمینهٔ مدیر همه سر جایشان |

شبیه‌سازی خطا/خالی/۴۰۱: `npm run simulate:error`، `simulate:empty`،
`simulate:unauthorized`، و بازگشت با `simulate:reset` (یا `/dev/design`).

## شبیه‌سازی حالت‌ها (فقط توسعه)

در `/dev/design` می‌توان همهٔ خواندن‌ها را روی «خطای شبکه»، «نتیجهٔ خالی» یا
«پاسخ ۴۰۱» گذاشت تا loading/empty/error/retry و مسیر «نشست نامعتبر → پاک‌سازی
مرکزی → هدایت به ورود» بدون بک‌اند قابل بررسی باشند.
