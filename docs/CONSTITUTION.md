# قانون اساسی وقتی‌نو — خلاصهٔ اجرایی برای همهٔ فازها

> نسخهٔ کامل در تاریخچهٔ پروژه موجود است؛ این سند چک‌لیست اجرایی است.

## هویت محصول
- **وقتینو**: اپ رزرو نوبت موبایل‌محور برای کسب‌وکارهای خدماتی.
- یک **User واحد** با قابلیت‌ها: مشتری / صاحب کسب‌وکار / کارمند — نه حساب جداگانه.
- ادمین **خارج از اسکوپ** است؛ هیچ route/placeholder ادمین ممنوع.

## فنی
- Nuxt 4 + Vue + TypeScript(strict) + Nuxt UI + Composition API.
- موبایل‌اول؛ طراحی از موبایل به دسکتاپ — نه برعکس. هدف نهایی: Capacitor/Android.
- Nuxt UI ابزار است نه هویت بصری؛ محصول نباید شبیه دموی Nuxt UI شود.
- معماری داده: `Page → Composable → Service(mock|api)`؛ `$fetch` پراکنده ممنوع.

## طراحی
- **Bold Modern**: مدرن، مطمئن، ممتاز، انسانی؛ بدون شیوهٔ «AI SaaS»
  (گرادیان/نئون/گلس‌مورفیسم/سایه‌بازی/کارت‌انبوه ممنوع).
- توکن‌محور؛ رنگ اصلی از یک نقطه (tokens.css) قابل تغییر؛ هگز در کامپوننت ممنوع.
- دارک‌مود از روز اول، دست‌ساز، با کنتراست سالم — در هر دو حالت تست شود.
- فارسی‌محور RTL-first: فونت Vazirmatn، ارقام فارسی، آیکون‌های جهت‌دار صحیح.
- Persian week: شنبه=۰ … جمعه=۶.

## UX
- هر صفحه: loading / empty / error / success / validation / destructive-confirm.
- رزرو = تجربهٔ درجهٔ یک؛ کاربر همیشه کسب‌وکار/خدمت/کارمند/تاریخ/ساعت/قیمت/وضعیت
  را بداند.
- mock data فارسی و واقع‌گرایانه؛ لورم‌ایپسوم و Test Business ممنوع.

## ساختاری
- سازماندهی دامنه‌محور؛ تایپ‌های دامنه در `app/types`.
- کامپیوننت‌لایه‌ها: primitive → Waqtino UI → feature → section → page.
- وضعیت‌ها تفکیک‌شده: auth/mode مرکزی؛ سایر stateها مینیمال.

## دیسیپلین فازها و Git (اجباری)
1. فاز را بدون جهش به آینده کامل کن.
2. `lint` + `typecheck` + `build` سبز + بازبینی تغییرات.
3. کامیت تمیز conventional → push به ریموت.
4. گزارش پایان فاز: موارد ساخته‌شده، تصمیم‌ها، فایل‌ها، چک‌ها، محدودیت‌ها،
   هش کامیت، وضعیت push — سپس توقف و انتظار برای فاز بعد.
5. اگر push به هر دلیلی (auth/remote/مجوز) شکست خورد: دلیل دقیق گزارش شود،
   کامیت محلی تمیز بماند، و موفقیت push جعل نشود.
